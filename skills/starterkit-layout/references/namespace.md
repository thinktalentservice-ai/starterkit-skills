# The `il-*` namespace, the two custom-property layers, and the cascade

Loaded on demand from [../SKILL.md](../SKILL.md). Inventories are scraped from
`@devopsnext/starterkit-layout@1.4.1`'s published `styles.css` (`5b4f865e944a`): **52 classes, 16
`--il-*` geometry properties, 29 `--il-t-*` token aliases.** Re-derive with the commands in the
skill's Staleness section rather than trusting these counts after a bump.

## The token contract

The package declares **nothing on `:root`**. Every token it reads is aliased onto its own scope:

```css
:is(.il-shell, .il-brand) {
  --il-t-fg2: var(--fg2, #8b93b5);
}
```

A CSS fallback applies only to an **absent** custom property, so your `--fg2` wins wherever you
define it and the vendored default renders the shell where you do not. Priority falls out of the
mechanism — there is no load-order rule to get wrong and no `@layer`. Rules are deliberately
unlayered so they beat unlayered global resets.

`.il-brand` is the second scope because `AuthLogo` renders on a login page, outside any shell, and
would otherwise have no tokens at all.

**The remote token sheet is never `@import`ed.** An `@import` is all-or-nothing — it would also ship
a `body` background, a Google Fonts request and a pile of component classes, and would need a CSP
allowance from every consumer. The alias block is generated by `pnpm sync:tokens` upstream from the
live design-system sheet, and `pnpm sync:tokens:check` fails CI when the vendored copy drifts. The
seed set is scraped from `styles.css` itself, so there is no hand-maintained list.

### Specificity, honestly

Unlayered beats an unlayered reset **only where this package's selector is more specific.** Against
an EQUAL-specificity Bootstrap rule — `.navbar` vs `.il-topbar`, `.dropdown` vs `.il-mega` — the
cascade falls through to source order, and a host importing Bootstrap after this sheet wins. Those
cases are written as compound selectors (`.il-topbar.navbar`, `.il-mega.dropdown`) so load order
stops mattering.

**If you add a rule whose class sits on an element that also carries a Bootstrap component class, do
the same** — write `.il-x.bootstrap-class`, or your rule flips on an import reorder.

## Light and dark

Dark is the default. The light palette is vendored the same way and fires on three selectors,
because a host can express "light" three ways:

```css
[data-mui-color-scheme="light"]                       /* MUI's attribute */
[data-theme="light"]                                  /* a bare data-theme */
:root:not([data-mui-color-scheme]):not([data-theme])  /* neither, + prefers-color-scheme: light */
```

The third is guarded on a root carrying neither attribute, so a host running dark mode on a
light-preference machine is not dragged into light. Set either attribute and the OS preference stops
being consulted.

**The same three selectors also paint `.il-content-area`**, so the content column follows the scheme
instead of showing the host's `body` through it. If you add a scheme-dependent rule, keep all three
in step — two of the three is the bug that only appears on one host configuration.

### The content column is painted in light only, and the asymmetry is the design

In dark, the floor (`--background`) sits *below* `--surface`, so cards read as raised and an opaque
column would only flatten them. In light the relationship inverts in effect — the floor sits below
`--card` — so an unpainted column reads as a grey field the white cards float on. Painting the column
removes that field **without** repointing `--background`, which `body`, MUI's
`palette.background.default` and Bootstrap's `--bs-body-bg` all still read. It is scoped to the
column and deliberately not to `body`, which also backs the sidebar gutter and the overscroll area.

**What it costs you.** If your preset sets light `--surface` and `--card` to the same white, the
column and every Card are now the same colour in light, and a Card is told apart only by its border
and shadow. Anything that painted itself `var(--surface)` in order to read as raised is flat-on-flat.
Give it `--surface-elevated` or a border. **Do not answer it with a rule on `.il-content-area`** —
the package owns that property at equal specificity, so source order decides and it flips on an
import reorder.

Two properties on `.il-content-area` became load-bearing the moment it painted, and both are worth
knowing before you fight them:

- **`min-height: 100vh`.** Below `lg` the shell is block layout, and a parent's `min-height` does not
  propagate to a block child's auto height. The sidebar and fixed topbar are both out of flow there,
  so the column is the only in-flow child and collapses to its own content — measured at 375×1600
  with an empty page as a 1541px band of `--background` under the paint. **`100vh`, not `100dvh`**,
  because it tracks `.il-shell { min-height: 100vh }`; mixing the units puts the column short by the
  mobile URL bar.
- **`box-sizing: border-box`, declared rather than inherited.** `.il-fixed-topbar.il-content-area`
  adds `padding-top`, and this package emits Bootstrap utility classes *without depending on
  Bootstrap* — so Bootstrap's global `* { box-sizing: border-box }` is a prerequisite the shell must
  not silently rely on for a height calculation.

Consequently: **do not give a page its own full-height background inside the column.** A second
full-height paint is either invisible or a seam. Size with
`calc(100dvh - var(--il-shell-top, 0px))` and paint only what must differ.

## `--il-*` — the 16 geometry properties you may override

One dash, not `--il-t-`. These are **not** design tokens; they are absent from the token sheet, and
the one-dash difference is exactly what keeps the codegen's `--il-t-*` scraper off them.

| Property | Default | What it positions |
|---|---|---|
| `--il-sidebar-width` | `240px` | open sidebar width |
| `--il-mini-sidebar-width` | `80px` | collapsed rail width |
| `--il-topbar-height` | `59px` | topbar height; read by `useHeaderAutoHide` |
| `--il-rail-center` | 40px | the icon rail line. The topbar mark, the sidebar avatar and every nav icon centre on it, so the mark sits directly above the icon column and the column does not move when the sidebar collapses |
| `--il-label-x` | 68px | where every text column starts — nav labels, captions, the sidebar username. Rows reach it with different gaps; the text column is the constant, the gaps are the slack |
| `--il-toggle-clearance` | `40px` | how far past the sidebar's trailing edge the collapse toggle sits, in both states. **Zero is not available**: an 80px mini column has 24px clear against a 36px `IconButton`, so pinning the toggle to the edge puts it on top of the mark |
| `--il-sidebar-width-neg` | `calc(-1 * …)` | off-canvas translation |
| `--il-shell-top` | `var(--il-topbar-height)`, `0px` when the header is hidden | what content offsets against |
| `--il-mark-size` `--il-mark-radius` `--il-mark-glyph` `--il-mark-glow` | derived from `size` | `BrandMark` geometry, written inline per instance: radius 0.3×, glyph 0.5×, glow blur 0.5× |
| `--il-mark-max-width` | `size × 5` | width cap on a **bare** mark, whose aspect ratio comes from a file the package never sees |
| `--il-brand-wordmark-height` | `32px` | height of an image wordmark (`wordmarkSrc`); the file decides the width |
| `--il-brand-wordmark-max-width` | `180px` | width cap on that image |
| `--il-brand-name-size` | derived | type size of the **text** wordmark — ignored when `wordmarkSrc` is set |

`ShellGeometry` (the `geometry` prop) maps 1:1 onto the first three via inline styles on the shell
element; numbers are treated as px, omitted fields leave the stylesheet default standing.

### Three ways to write these wrong, all silent

1. **`-var(--il-sidebar-width)`** compiles to invalid CSS, which browsers drop **silently** — and the
   dropped declaration is the one hiding the mobile drawer below `lg`, so the drawer simply appears
   with no error anywhere. Write `calc(-1 * var(…))`.
2. **`--il-shell-top: 0`** — a bare `0` invalidates every downstream `calc()`. It must carry a unit:
   `0px`.
3. **A derived property declared on `:root`.** A custom property resolves its `var()`s against the
   element it is **declared** on, and `.il-shell` is where the `geometry` prop writes
   `--il-mini-sidebar-width`. A derived value on `:root` freezes the default and silently ignores the
   prop. **Re-declare on `.il-shell`.**

**On `bare` marks specifically:** while `bare`, the glyph is 1.0× and `--il-mark-size` stops being a
box and becomes a HEIGHT — the file decides the width. The width cap must be **absolute**, never
`max-width: 100%` on the inner `<img>`: a percentage resolves against the mark, whose own width is
`auto` and therefore depends on that child. The circularity collapses to the `min-width` floor, and a
759×458 logo measures 32×32 with every rule apparently applied. Same reasoning for
`--il-brand-wordmark-max-width`, whose collapsing wrapper is `width: auto` mid-animation.

## `--il-t-*` — the 29 vendored token aliases

**Generated. Never hand-edit, and never set one from your app** — set the design token it reads, and
the alias picks it up through the `var(--your-token, …)` fallback.

```
border  danger-on-solid  danger-solid  danger-solid-hover  fg-muted  fg1  fg2
font-body  font-heading  glass-border  gradient-avatar  gradient-avatar-ink
gradient-secondary  hover-overlay  primary  primary-bg  primary-border
primary-channel  primary-text  radius  radius-card  radius-pill  secondary-channel
secondary-text  shadow-dropdown  sidebar-bg  surface  surface-elevated  topbar-bg
```

Each is `--il-t-X: var(--X, <vendored default>)`, in three blocks: base dark, the
`[data-mui-color-scheme="light"]` / `[data-theme="light"]` pair, and the `prefers-color-scheme: light`
fallback guarded as `:root:not([data-mui-color-scheme]):not([data-theme])`.

**The three `danger-*` aliases are the trap.** They style `ProfileMenu`'s logout link. An estate that
never defined `--danger-solid`, `--danger-solid-hover` and `--danger-on-solid` gets the vendored
fallbacks — which is a shipped colour nobody chose. The fix is to define those three tokens, **not**
to restyle `.il-profile-logout`.

## The 52 classes

Package-owned. Do not restyle them from app CSS: `.il-shell` and `.il-brand` are also the token alias
scope, so redefining either can strand the alias block.

- **Shell** — `il-shell` `il-content-area` `il-sidebar-area` `il-sidebar-overlay` `il-is-mini`
  `il-hide-mini` `il-show-sidebar` `il-fixed-topbar` `il-fixed-sidebar` `il-header-hidden`

  `il-role-badge` `il-avatar` `il-avatar-btn`
- **Dropdowns** — `il-dd` `il-dd-end` `il-dd-header` `il-dd-width` `il-mega`
- **Profile panel** — `il-profile` `il-profile-id` `il-profile-avatar` `il-profile-initials`
  `il-profile-text` `il-profile-name` `il-profile-email` `il-profile-actions` `il-profile-logout`
- **Sidebar** — `il-sidebar` `il-sidebar-box` `il-sidebar-nav` `il-sidebar-user` `il-sidebar-username`
  `il-sidebar-avatar` `il-nav-icon` `il-nav-caption` `il-submenu` `il-submenu-toggle`

Two are worth knowing as **hooks for your own selectors** rather than as things to restyle:
`il-active-link` (the current row) and `il-is-mini` (the collapsed state on the shell root).

## RTL

The package flips only its **own** shell geometry, keyed off `[dir="rtl"]`, which `FullLayout` sets.
Flipping Bootstrap's utilities is the host's job — shipping a second copy of that sweep would fight
whatever you already load. If your RTL overrides are scoped under a class, pass that class to
`FullLayout` as well; the `dir` attribute alone will not trigger them.

## Drift is gated, not remembered

A fingerprint over `.d.ts` files does not see CSS rule bodies. A release can repaint the shell, add a
token alias and rewrite vendored fallbacks while every type fingerprint stays identical — 1.1.0 did
exactly that. If you keep a drift gate in your repo, compare the version, **both** type surfaces,
**and** the scraped class and geometry inventories, so a renamed class — invisible to a type checker
— fails the build.
